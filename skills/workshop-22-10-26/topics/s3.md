# S3 — Simple Storage Service

> **In one sentence:** S3 is the AWS **object storage**: it holds any file (image, HTML, JS, backup) practically without limit, durably and cheaply, reachable over HTTP.

> **Docs:** [What is Amazon S3?](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) · [S3 product page](https://aws.amazon.com/s3/)

> **Course (Udemy path, Week 1):** sections *S3 Introduction*, *Advanced S3* and *S3 Security*. **Live demo:** the workshop site is served from a private S3 bucket through CloudFront at https://dhdwvoyc20mo5.cloudfront.net/ (the `Server: AmazonS3` response header shows the origin).

---

## 1. Analogy to remember

S3 is a **Google Drive/Dropbox for applications**, but:

- without "real" folders (it is one big flat space of keys);
- accessed through API/HTTP, not as a "mounted disk";
- you pay **only for what you use**.

---

## 2. What it is (basic concepts)

| Term | Meaning |
| ---------- | ---------------------------------------------------------------------------------- |
| **Bucket** | The top-level "container". Every object lives inside a bucket |
| **Object** | The file + metadata. Size from **0 bytes up to 5 TB** |
| **Key** | The object's "path/name", e.g. `img/products/shirt.jpg` |
| **Region** | A bucket is created in **one region** (the data stays there unless you replicate it) |

**Essential points:**

- **A bucket name is globally unique** across **all AWS accounts**, in **all regions**. That is why simple names like `store` are already taken; use something like `mystore-prod-2026`.
- Naming rules: lowercase letters, numbers, hyphens, 3 to 63 characters.
- **"Folders" in S3 are an illusion:** `img/products/shirt.jpg` is **one single key**. The console only _shows_ the prefix `img/products/` as a folder.
- **Durability of 99.999999999% (11 nines)** in the standard classes: data is replicated across multiple AZs. In practice, losing an object is extremely unlikely.
- **Strong read-after-write consistency:** you wrote it, you read the new data.
- Practically unlimited scale, with no capacity provisioning.

> **Docs:** [Bucket naming rules](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucketnamingrules.html) · [What is Amazon S3?](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)

## 3. Basic usage

- **Console:** create a bucket → _Upload_ files.
- **CLI:**
  ```bash
  aws s3 mb s3://my-unique-bucket             # create a bucket
  aws s3 cp index.html s3://my-unique-bucket/ # upload one file
  aws s3 sync ./dist s3://my-unique-bucket/   # sync a folder (site deploy)
  aws s3 ls s3://my-unique-bucket/            # list
  ```
- **Use cases:** hosting static content, product images, backups, _data lakes_, logs, build artifacts.

> **Docs:** [`aws s3 sync`](https://docs.aws.amazon.com/cli/latest/reference/s3/sync.html) (it only uploads what is new or changed; deleting what disappeared needs `--delete`)

### Useful features (and how not to mix them up)

| Feature | What it does |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Versioning** | Keeps **several versions** of the same object. Lets you **recover** an overwritten or deleted version. Once enabled it can only be **suspended**, not disabled |
| **Lifecycle rules** | **Automate** transitions between classes and **expiration** (e.g. move to Glacier after 90 days; delete after 1 year). They do not recover versions by themselves |
| **Requester Pays** | The person who **downloads** pays the download cost, not the bucket owner |
| **Transfer Acceleration** | Speeds up **long-distance upload/download** using the edge location network |
| **Replication** | Copies objects to another bucket (same or another region) |
| **Presigned URL** | A **temporary** signed URL that gives access to **one** object without making the bucket public |

> **Docs:** [Versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html) · [Lifecycle management](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html) · [Requester Pays buckets](https://docs.aws.amazon.com/AmazonS3/latest/userguide/RequesterPaysBuckets.html) · [Transfer Acceleration](https://docs.aws.amazon.com/AmazonS3/latest/userguide/transfer-acceleration.html) · [Replication](https://docs.aws.amazon.com/AmazonS3/latest/userguide/replication.html) · [Presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

## 4. Storage classes (tiers)

> The idea: **the less you access the object, the cheaper the storage** (and the more expensive/slower to retrieve).

| Class | When to use |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| **S3 Standard** | **Frequent** access (site, catalog images). The default |
| **S3 Intelligent-Tiering** | **Unknown/variable** access pattern: AWS moves objects between tiers by itself |
| **S3 Standard-IA** (_Infrequent Access_) | **Rare** access, but needs a fast response. Cheaper to store |
| **S3 One Zone-IA** | Like IA, but in **a single AZ** (cheaper, less resilient). Re-creatable data |
| **S3 Glacier Instant Retrieval** | Archive, accessed **a few times**, with millisecond response |
| **S3 Glacier Flexible Retrieval** | Archive; retrieval in minutes to hours |
| **S3 Glacier Deep Archive** | The **cheapest**; long retention (years); retrieval in hours |
| _(S3 Express One Zone)_ | Just mention: ultra-low latency, for intensive workloads |

**In practice:** the most common are **Standard**, **Intelligent-Tiering**, **IA** and **Glacier** (the "archive family"). **Lifecycle rules** move objects between them automatically. For an active static site, **Standard** is the choice.

> Prices and fine details change; check https://aws.amazon.com/s3/pricing/ before quoting numbers.

> **Docs:** [Understanding and managing storage classes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html) · [Storage classes overview](https://aws.amazon.com/s3/storage-classes/) · [S3 pricing](https://aws.amazon.com/s3/pricing/)

## 5. Security (what must not be missing)

**Principle:** a bucket is born **private**. Keep it that way unless there is a very strong reason.

1. **Block Public Access** (BPA): a master switch that **blocks public access**, even if someone makes a mistake in a policy. **On by default** for new buckets. Keep it on.
2. **Who can access?** Three mechanisms:
   - **IAM policies** (identity-based): "this user/role can...".
   - **Bucket policy** (resource-based): "this bucket accepts access from...". This is where CloudFront is granted access (via OAC).
   - **ACLs**: legacy. Today they are **disabled** by default (_Object Ownership: bucket owner enforced_). Prefer policies.
3. **Encryption:**
   - **At rest:** every new object is encrypted by default with **SSE-S3**. Alternatives: SSE-KMS (keys in KMS, with control and auditing), SSE-C.
   - **In transit:** use **HTTPS** (you can _require_ it with a bucket policy using `aws:SecureTransport`).
4. **Versioning** + (optional) **MFA Delete**: protection against accidental deletion.
5. **Logging/auditing:** _server access logs_ and **CloudTrail** to know who accessed what.
6. **Presigned URLs:** share a file temporarily without opening the bucket.
7. **Object Lock:** WORM (immutable), for regulatory retention. Just mention.

**Example bucket policy (CloudFront via OAC), which you will see in the demo:**

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudFrontServicePrincipal",
      "Effect": "Allow",
      "Principal": { "Service": "cloudfront.amazonaws.com" },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-store-bucket/*",
      "Condition": {
        "StringEquals": {
          "AWS:SourceArn": "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DISTRIBUTION_ID>"
        }
      }
    }
  ]
}
```

_Reading:_ "only **CloudFront** can read the objects, and only **my distribution**."

> **Docs:** [Blocking public access](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html) · [Bucket policies](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucket-policies.html) · [Controlling object ownership and disabling ACLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/about-object-ownership.html) · [Default encryption](https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-bucket-encryption.html) · [Security best practices](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html) · [Server access logging](https://docs.aws.amazon.com/AmazonS3/latest/userguide/logging-with-S3.html) · [Logging with CloudTrail](https://docs.aws.amazon.com/AmazonS3/latest/userguide/cloudtrail-logging.html) · [Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html)

## 6. S3 for a static site: two ways

| | **A) S3 website hosting** | **B) Private S3 + CloudFront (OAC)** ✅ |
| ------------------------- | ---------------------------- | ------------------------------------------- |
| Bucket | **Public** | **Private** (BPA on) |
| HTTPS | ❌ HTTP only on the S3 endpoint | ✅ HTTPS (CloudFront certificate or ACM) |
| CDN/cache | ❌ | ✅ |
| Custom domain with HTTPS | ❌ | ✅ |
| Recommended | Quick test | **Production** |

**Recommendation:** use **B**: it combines S3 + security + CloudFront (see `cloudfront.md`).

> ⚠️ With OAC, CloudFront reaches the bucket's **REST** endpoint (not the "website" endpoint). Consequence: the **Default Root Object** (`index.html`) only works at the root `/`. For `/products/` to become `/products/index.html` you need a **CloudFront Function** or you adjust the links.

> **Docs:** [Hosting a static website using Amazon S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/WebsiteHosting.html) · [Restrict access to an S3 origin (OAC)](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html)

## 7. Common beginner pitfalls

- Trying simple bucket names and getting "name already taken".
- Thinking S3 has real folders or that it is a _filesystem_.
- Turning **Block Public Access** off "to make it work" instead of setting up OAC correctly.
- Forgetting that **versioning** raises cost (old versions take space): combine it with lifecycle to expire old versions.
- Putting frequently accessed data in Glacier (slow/costly retrieval).
- Using the _website_ endpoint expecting HTTPS.

## 8. Hands-on practice (study account; costs stay low for small volumes)

1. Create a bucket with a unique name, **keeping Block Public Access on**.
2. Upload a simple `index.html`. Try to open it through the object URL and see **Access Denied** (that is the correct behavior!).
3. Turn on **Versioning**. Upload the same file changed 2 times and use _Show versions_. Delete it and recover it.
4. Create a **Lifecycle rule** (transition to IA after 30 days) and read the summary.
5. Generate a **presigned URL** from the CLI: `aws s3 presign s3://bucket/index.html --expires-in 300`.
6. Look at the workshop live demo (`curl -I https://dhdwvoyc20mo5.cloudfront.net/`): the `Server: AmazonS3` header shows an S3 origin behind CloudFront.
7. At the end, **empty and delete** the bucket.

> **Cost note:** the AWS Free Tier for new accounts is credit-based (since 15 July 2025: up to USD 200 in credits, a free plan that lasts 6 months, and credits to be used within 12 months). Check the current terms at https://aws.amazon.com/free/ and on the S3 pricing page.

> **Docs:** [`aws s3 presign`](https://docs.aws.amazon.com/cli/latest/reference/s3/presign.html) · [AWS Free Tier](https://aws.amazon.com/free/)
